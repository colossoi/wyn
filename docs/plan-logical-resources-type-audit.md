# `plan_logical_resources`: struct and enum audit

Reviewed and updated 2026-09-10 in the working tree, after implementing the resource-planning refactor.

The audit covers every struct and enum declared in `allocation/mod.rs`, `residency.rs`, `cost.rs`, and `host_length.rs`, including nested test modules. There were **17 definitions** when this review started. Two have been removed; **15 remain**. `host_length.rs` and the separate allocation test files declare no structs or enums. Imported graph and program types are not counted as local definitions; the immediately relevant ownership contracts are reviewed separately below.

A type earns its place when it expresses a useful distinction, owns related state that would otherwise have to be synchronized, or gives several operations a coherent context. Merely shortening an argument list is weaker evidence. A private record is also not automatically a proof of validity: several relationships here are established by the planner's checks, rather than by the Rust field types themselves.

## Objectives used for the review

These are the same objectives as the [original pass audit](C:/Users/gmiller_amilarcap/dev/wyn/docs/plan-logical-resources-objective-audit.md):

| ID | Library outcome |
| --- | --- |
| O1 | A consistent host resource contract, including forward size references and explicit external sizing. |
| O2 | Usable results across execution boundaries, including both runtime-array capacity and actual length. |
| O3 | Preserved computation, effects, retained outputs, and producer-before-consumer execution. |
| O4 | Correct host publication and internal output routes. |
| O5 | Avoid expensive repeated scalar work when materialization is justified. |
| O6 | A coherent target-independent stage/resource plan that respects topology policy. |

## Supporting ownership types and remaining design debt

The local definitions depend on a few shared structures whose contracts matter more than removing another short declaration.

- [`LogicalResourceArena`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:449) earns its place as the owner of resource identities and host/compiler lookup indexes. The indexes refer into the same arena; they are not competing resource collections. `ResourceAllocationBuilder` supplies the additional admission checks needed while processing interfaces.
- [`ResourceProgramData`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1500), [`ResidencyProgramData`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1558), and [`AllocatedProgramData`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1597) have distinct ownership jobs: shared resource/program data, the mutable stage builder and resource-to-flow index, and the completed stage graph. Stage bodies now live in the builder itself. The old parallel `stage_ids` map and final entry-ownership join are gone.
- There is still an architectural loophole in the generic program shape: these staged program aliases inherit `Program::entry_points`, but allocation supplies an empty vector and finalization ignores that field. There is one body owner in the implemented path, but the type still permits an irrelevant second collection. Eliminating that slot requires changing the shared program shape or introducing a staged-program shape; the phase tags do not solve it. This is a more substantial ownership improvement than renaming a private output record.
- [`StageOrigin`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1518) combines authored/generated provenance with an optional semantic space. That space affects actual dispatch in the scheduler, while the detailed [`GeneratedStageKind`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1509) primarily supplies provenance and diagnostics. The representation permits combinations the allocation constructors do not produce, such as a generated array stage without a space. A future consolidation with `FixedMaterializationKind` should preserve the scheduling distinction in the payload, rather than replacing it with nullable fields and assertions.
- [`ResidentStorage`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/program.rs:1546) and [`filter::RuntimeStorage`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/soac/filter.rs:185) should remain distinct. General staged values may have no separate length resource; a bound runtime Filter result must have one. Sharing the field names `data` and `length` is not sufficient reason to weaken the latter contract to an optional length.

The remaining priorities are therefore the shared staged-program shape and stage-origin classification. Within this pass, the output records now remove more correspondence bookkeeping than they introduce. Further wrappers, generic typestate parameters, or one universal materialization enum would need a concrete reduction in callers to justify their cost.

## Tests: feature versus representation

The refactor removed the unit test that asserted the old structured-prefix policy enum classification. Its replacement compiles the same structured storage-prefix feature through both permitted-generated and authored-only topology: the former produces a shared scalar prelude, while the latter retains the computation in its authored stage and emits validated SPIR-V. This protects library behavior without requiring an internal `Required` variant.

The existing residency fixpoint test has two different kinds of assertion. Re-running residency without creating more resources or stages checks a meaningful pass property. Its exact ordered vector of `GeneratedStageKind` labels is more representation-sensitive. If the stage-origin enums are consolidated, preserve idempotence and the required producer/consumer dependencies; do not retain an obsolete enum or collection order solely to satisfy that vector assertion.

Tests for unfinished versus externally sized host resources, conflicting Filter storage, topology restrictions, retained live values, and executable output validity still guard their features. None needed to be weakened for the two type removals or the `InputReplacement` constructor change.

## Follow-up: merged sub-pass traversals

Two repeated traversals have been removed without adding any struct or enum:

- [`plan_required_residency`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/allocation/residency.rs:314) replaces the separate structural-result and scalar-result discovery passes. It walks operations once, retaining scalar candidates and their consumer sets. Scalar legality and projection are deferred until structural candidates in every entry have been exhausted, preserving global priority and error ordering. Each entry still shares one lazy invariance check, and each materialization still restarts analysis.
- [`realize_graph_dynamic_publication`](C:/Users/gmiller_amilarcap/dev/wyn/wyn-core/src/egir/allocation/mod.rs:539) now also collects bound Filter result-type updates during its existing traversal. The separate `realize_filter_result_types` graph scan is gone. Publication controls storage binding; every bound runtime Filter gets its result type updated, including those with no publication slots. Collected type updates are applied after the traversal releases its graph borrows.

Together these changes remove 50 production lines. The full core library suite was rerun: **1,674 passed, 17 ignored**. Existing tests required no changes; the mergers preserve their behavior rather than changing assertions to match a new representation.
