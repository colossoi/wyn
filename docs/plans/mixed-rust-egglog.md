# A Rust memory IR with local egglog queries for Wyn

Proposal based on Wyn `3e911a09` and the Futhark revision recorded by this checkout, `3a5bc16d`.

**Build a structured memory IR whose Rust dependency graph can be traversed without inspecting arithmetic operators.** For `x = a + b` and `y = a - b`, a dependency query returns the same inputs for each result. The two operations retain distinct identities and typed definitions. A graph walk follows the inputs. A pass that needs to distinguish addition from subtraction looks up the operation’s definition. This also preserves operand order and multiplicity for operations such as `b - a` and `a - a`. Keep these direct edges and their enclosing regions in Rust between ownership-checked TLC and host/shader lowering. Egglog answers questions about equivalent expressions, transformation legality and storage choices. Shader SSA is a downstream output of lowering.

**Implementation status (2026-11-23).** One Rust graph owns executable memory dataflow from TLC import through host and shader lowering. Rust owns call sites, regions, ordered operations, values, iteration domains, and certificates. Simplification edits the authoritative graph directly. Parallel fusion retains a typed Rust body through successive splices and cleanup. Egglog retains symbolic terms and derives feasibility and cost facts. Physical planning freezes execution and storage decisions before lowering. Several structural edits still invalidate whole-program proofs. [Executable graph](../../wyn-core/src/egglog/graph.rs) · [Simplifier](../../wyn-core/src/egglog/memory.rs) · [Parallel fusion and motion](../../wyn-core/src/egglog/fusion/parallel.rs) · [Frozen execution plan](../../wyn-core/src/egglog/execution.rs)

**Performance requirement.** Eliminate whole-program refreshes after edits throughout the compiler. Update use lists, region ownership, order, and other directly affected facts as part of each edit. Recompute a scoped fact only when its inputs change. Propagate a changed function summary through its actual consumers, including recursive components where needed. A full refresh is a last resort for a dependency whose effects genuinely reach the whole program and cannot be maintained or recomputed more narrowly. Inspect the code for each such exception and record its trigger, the facts it refreshes, and why a narrower update cannot preserve correctness. Initial construction of the Rust graph and initial analysis required by a consumer are incurred once per compilation. ## Where the boundary belongs

**Value identity.** A `ValueRef` identifies a region parameter by region and position, or an operation result by producer and position. An operand stores that reference directly. The importer must bind a source name to the reference of its right-hand side. In `let t = a + b in let x = t in let y = x in (t, y)`, the addition supplies one `ValueRef`. Looking up `t`, `x` or `y` returns that same reference, so the tuple contains it twice even with every optimization disabled. A plain name binding creates no operation. This works for any runtime value, including a parameter whose value the compiler never learns. Equal references establish identity immediately. Distinct definitions can still compute equal values, which a pass can ask egglog to prove.

A reference denotes one value for each execution of its definition. A nested region may capture an available outer value. A loop body binds its carried parameter anew on each iteration, and a branch yields the result of the selected arm. In the true arm of `if t == 0`, a query may assume the value of `t` is zero. That fact applies after the join only if it holds on every incoming path. A reference to an array view likewise identifies the view. Which writes a later read can observe is a separate storage question.

Futhark makes this distinction in its fusion pass. The core IR stores a typed binary operator and its two operands in each binary expression. The fusion pass builds a per-body graph from the names used by each statement. For ordinary scalar arithmetic, changing `+` to `-` with the same operands leaves those dependency edges unchanged. The `StmNode` label retains the underlying statement, so a pass can inspect the precise operator when it needs to. There is no requirement for a separate opcode table. Wyn already separates indexed `Input` rows from `OperationPayload` in egglog. The change is to give Rust direct access to those edges and typed definitions. [Futhark operation syntax](../../extra/futhark/src/Futhark/IR/Syntax.hs) · [Futhark operands](../../extra/futhark/src/Futhark/IR/Syntax/Core.hs) · [Fusion graph construction](../../extra/futhark/src/Futhark/Optimise/Fusion/GraphRep.hs) · [Wyn operand and payload writer](../../wyn-core/src/egglog/dataflow/ir.rs)

Futhark uses the term *explicit memory* for a later refinement. It describes a materialized array with its element type, shape, named memory block and an index function mapping coordinates to element offsets. An operation can return an array in an existing block or bring a block into scope with its result. Wyn can introduce these storage decisions when planning a materialization. The Rust dataflow representation is useful from the first scalar addition onward. [Futhark memory bindings and returns](../../extra/futhark/src/Futhark/IR/Mem.hs) · [Futhark index functions](../../extra/futhark/src/Futhark/IR/Mem/LMAD.hs)

For example, suppose a function returns a slice of its input. The Rust memory IR records the slice’s shape and index mapping and the fact that the result refers to the input’s backing. Returning that slice exposes the backing to the caller even though the callee’s local name goes out of scope. If the function returns a materialized copy, the result can have independent storage. Branch yields and loop carries describe how those array bindings flow between regions. Keep a map result logical while fusion can eliminate it. Attach a concrete storage decision at planning time when a surviving result needs materialization.

| Computation | Representation and owner | What crosses the boundary |
| --- | --- | --- |
| Functions and calls | Rust stores direct call sites, adjacency and entry roots. A reachability walk finds live functions. Strongly connected components (SCCs) identify recursion. | Export a callee summary where a rule consumes one, such as exposed parallel work or effects. |
| Memory dataflow | Rust stores functions and ordered regions of array producers, consumers, views, updates and parallel operations. Direct operands, result uses, and declared read, write and consume behavior are available to a graph walk. | Publish the relevant use sites, view origins, shapes and ownership diets. Egglog can follow these facts to derive possible backing roots and access conflicts. |
| Control flow | The Rust memory IR owns the bodies and yields of branches, loop initial values and backedges, callbacks, reducers and combiners. A pass can derive block adjacency from these edges when it needs reachability. | Supply the branch, carry, capture and call-summary facts needed by a query. A use in another arm or a later iteration can affect the answer. |
| Scalar and index algebra | A pass requests equality or simplification for particular typed expressions in one region. Existing Rust evaluators handle primitive folds. | Submit the relevant pure definitions and available leaves. Return a proven equality, a cheaper expression, or an inconclusive result. |
| Fusion and motion | Rust enumerates candidates on the current body dependency graph, tests reachability and applies edits. Egglog checks domain, shape, access and policy conditions for those candidates. | Candidate IDs, structural preconditions and relevant resource summaries go in. A legal rewrite and its required conditions come back. |
| Execution and allocation planning | Egglog relations express feasibility. Functions derive extents, byte sizes, layout, reuse/snapshot eligibility, work and target-dependent strategy. Rust freezes compatible choices, assigns physical identities and emits instructions. | Pass explicit target features, topology policy and cost model. Return typed decisions keyed by logical operation or buffer. Mutually exclusive plans remain distinct candidates. |

The migration point is the existing TLC-to-memory-IR importer. Today `Program<Stage>` owns an `EGraph`, and even `OperationId` and `RegionId` wrap engine values. `Query::operations` scans the ownership table and sorts to recover a region’s statements. The simplifier can then edit one operation and enter `analysis::ensure` and `planning::analyze` again. Storing those bodies and edges directly in Rust addresses this source of repeated work while preserving the maps, scans and reducers used by fusion. ## How the two sides cooperate

**Identity and lifetime.** Give executable occurrences stable typed Rust IDs. Cloning an operation creates a fresh occurrence even when it computes an equivalent result. Build the structural indexes once and maintain them during edits. Keep the inputs of each egglog proof tied to the relevant graph facts and target policy. Map Rust IDs to opaque leaves or keys for that solve, and keep engine handles inside the adapter. Refresh callers that use a changed exported summary, and solve recursive summaries to a conservative fixed point within their SCC. A proof involving two bodies depends on facts from both. Check that its inputs still hold before applying it.

**Local expressions on demand.** A fusion pass comparing two views might ask whether `offset + (i + 1) * stride` and `(offset + i * stride) + stride` select the same element. Take the two roots, follow just their pure scalar definitions in scope, and treat previously computed inputs as opaque leaves. Supply only the facts valid at the proposed use, including any bounds needed by the integer rewrite. Test whether the roots become equal under Wyn’s arithmetic semantics. The pass needs only that answer. A simplifier can use the same mechanism with one root and request a cheaper expression. If a leaf came from a load, it denotes the value already read. Its producer stays in place.

Try direct identity and the existing constant folder first. For a remaining question, use a small ruleset with a rule-round and term-growth budget. Inconclusive equality leaves the proposed fusion unproved, and inconclusive simplification leaves the expression as written. Requests can share a loaded ruleset or batch related roots from the same scope. They need no persistent program-wide expression database. Keep branch assumptions local and apply floating-point rewrites only under the required NaN, signed-zero and rounding semantics. [Current scalar rules](../../wyn-core/src/egglog/scalar/simplify.egg) · [Scalar evaluator](../../wyn-core/src/egglog/scalar/fold.rs)

**Who should determine lifetime overlap and escape?** Rust should compute which values can still be used after a given operation. A backward walk over the memory IR can answer this for one body, including branch yields, captures and simultaneous loop carries. Multiple candidate allocations can use the same result. Return and call operands, view-of edges, and writes are also direct observations Rust can supply.

Give egglog the storage question for a particular candidate. Suppose `v` is a slice of `a`, a call returns `r` backed by its argument `v`, and `r` is read after a proposed overwrite of `a`. Rust supplies the read of `r`, the slice edge and the callee’s result-to-argument summary. Egglog composes them to show that the old backing is still observable through `r`. The last direct use of `a` can be long past. A proved disjoint index range can permit the overwrite. An unknown callee effect leaves it unproved. The same argument applies if the caller returns `r` and thereby exposes the backing to its caller. Derive reusable result-to-argument and escape summaries once per relevant body revision. Reuse their results across call sites.

This division puts backing provenance, escape through aliases, and interference for a proposed reuse in the same rules that consume ownership, layout and synchronization facts. It also avoids exporting a full control-flow graph for each question. At the later workgroup allocation stage, ordinary last use is insufficient because an access from another lane can remain pending until a barrier. Include pending accesses when checking a pool pair. Rust commits the resulting storage assignment. [Resource and liveness rules](../../wyn-core/src/egglog/analysis/resources.egg) · [Reuse and snapshot rules](../../wyn-core/src/egglog/planning/reuse.egg) · [Workgroup interference](../../wyn-core/src/ssa/workgroup_storage.egg)

**Cost of crossing.** Issue queries when a pass needs them. Batch multiple requests when they share inputs and assumptions, or when several allocation candidates compete for one backing. Measure schema setup, export, rule execution, extraction and application separately. Skip empty batches. Keep completed decisions in Rust and discard obsolete facts on edit.

**Completeness of a decision.** Scope a storage query by the proposed allocation, following relevant paths, possible aliases and callee summaries as far as necessary. Return permission to reuse only with complete inputs and a settled proof. An omitted use or an unavailable callee summary must never look like an empty set of effects. An inconclusive storage query retains separate allocations. Preserve staged evaluation where today’s rules consume negative facts after a fixpoint. A required legality check must finish, select an independently safe implementation, or return its diagnostic.

In `let x = f in (f(7), x(7))`, the importer should emit two call operations with the same target. The call graph can read that target directly. Its edges describe known calls. The general value-identity rule above also covers data and values whose identity is known while their contents or call target remain unknown.

Exercise each milestone through the normal compiler entry point. Establish a release baseline on full applications before changing the production path, and keep the old compiler binary for output comparisons. ## Metadata during pre-fusion simplification

This is the next Stage 2 milestone. `memory::simplify` asks `planning::analyze` for facts each time an edit restarts the loop. Replace that call with queries for the facts each rewrite needs. Start with the outer-length proof used by length forwarding. Keep facts that depend only on an unchanged type, such as its byte size, available throughout the compile. Track the inputs of value-dependent facts, including shape operands and loop carries, against the live Rust graph. [Simplifier loop](../../wyn-core/src/egglog/memory.rs) · [Metadata rules](../../wyn-core/src/egglog/planning.rs)

When an input changes, use the graph's use edges and the facts' dependencies to identify which consumers need a new answer. Follow captures, yields, loop carries, and calls when they carry the change. Ask egglog to solve only the affected facts needed by a consumer. If a recomputed fact has the same result, stop propagating that change. A loop or recursive call cycle can require solving its affected members together. Delete the whole-program query from the loop once its last consumer uses the scoped facts.

Length forwarding, pure scalar folding, and explicit scratch extents preserve their result identities and repair operand and capture edges in place. The simplifier settles shape-independent edits before it asks for shape facts. The solver propagates lengths on direct edges and tracks longer proofs for loop carries and reducer parameters. ## Research behind the split

- **Futhark’s call graph** records direct call sites per function and discovers callees from entry points and constants. Its fusion pass constructs a dependency graph for one body, adds consumption and alias edges, tests reachability for the proposed fusion, and contracts successful pairs. Wyn can reuse that division between candidate discovery and legality while retaining its own fusion policies. [CallGraph.hs](../../extra/futhark/src/Futhark/Analysis/CallGraph.hs) · [GraphRep.hs](../../extra/futhark/src/Futhark/Optimise/Fusion/GraphRep.hs) · [Fusion.hs](../../extra/futhark/src/Futhark/Optimise/Fusion.hs)
- **Futhark exposes some indexed accesses as array inputs.** Its scalar simplifier handles both operand orders of add–subtract cancellation. Its SOAC simplifier rewrites same-lane indexing over `iota` into an implicit map input. Its fusion pass can also move a supported result slice onto the producer's inputs. A general gather can read different producer lanes and can repeat work if each consumer recomputes its element. Futhark's filter lowers to flags, scan, and scatter. Wyn's shared proof is about same-lane loads in its explicit memory IR, including loads whose packed coordinates disappear when the consumer runs with the filter predicate. [Scalar simplification](../../extra/futhark/src/Futhark/Optimise/Simplify/Rules/Simple.hs) · [Map indexing](../../extra/futhark/src/Futhark/IR/SOACS/Simplify.hs) · [Fusion through slices](../../extra/futhark/src/Futhark/Optimise/Fusion/TryFusion.hs) · [Filter implementation](../../extra/futhark/prelude/soacs.fut)
- **Futhark’s memory passes** separate last uses and interference from physical assignment. Its GPU memory-block merger passes the interference graph and memory spaces to a greedy coloring algorithm, computes the maximum size for each color and emits allocations. For Wyn, that suggests a precise input for egglog allocation rules and a clear point at which Rust commits storage. [LastUse.hs](../../extra/futhark/src/Futhark/Analysis/LastUse.hs) · [Interference.hs](../../extra/futhark/src/Futhark/Analysis/Interference.hs) · [MemoryBlockMerging.hs](../../extra/futhark/src/Futhark/Optimise/MemoryBlockMerging.hs)
- **Cranelift’s e-graph design** keeps effecting instructions in the CFG and elaborates chosen pure expressions where their operands are available. That is a precedent for the expression boundary. Starting within one Wyn region makes the first extraction easier to validate. [Cranelift e-graph RFC](https://github.com/bytecodealliance/rfcs/blob/main/accepted/cranelift-egraph.md)
- **Egglog** supports both keyed functions with merge behavior and equivalence classes with cost-based extraction. Use keyed functions and relations to combine planning facts, and e-classes where alternatives really are interchangeable. Wyn’s speedup will depend on how much data and repeated work that choice eliminates. [Egglog paper](https://doi.org/10.1145/3591239) · [Egglog 3.0 extraction models](https://egraphs-good.github.io/egglog/docs/egglog/extract/index.html)
